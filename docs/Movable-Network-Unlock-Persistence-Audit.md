## Findings and implementation

All 12 saved sections and 28 pieces were enumerated above. No two sections or pieces have byte-identical serialized bodies after excluding only the root name. This is an exact duplicate check, not proof that differently serialized graphs can never be equivalent. No generic name-based merging was introduced.

`MovableSectionObjects` was traced through the section converter and factory ownership list: unchanged source sections/pieces/lanes are returned directly. A private Piece is created only when stationary object producers or track end-object production changes; a Section is copied only when its piece/subsection references change. Caches share each result per source within one bridge. Source isolation remains enforced. Native lanes, prices and geometry references remain in the cloned data. Signals remain network-owned; stationary visible attachments are removed or replaced by lighting-only producers because their moving visuals belong to the mechanism.

The per-file table records retained data and references. It is not a complete field-by-field comparison against every donor: original-source provenance is not serialized for each private network copy. The code path establishes the intended mutation scope; further semantic merging would require proving equivalence of all component fields and referenced resources, not just width or names.

Unlock 1 and Unlock 3 are identical empty native gates. The previous top-level Unlock 0 is also an unnecessary wrapper around a gate that can live directly on the root network. `BridgeNativeUnlock.Apply` now shares nested groups with equal RequireAll/RequireAny reference sets within the current bridge, removes duplicate children, and embeds the outer gate directly into root/auxiliary networks. It does not flatten independent OR groups or share private groups across bridges. Native progression leaves remain original references.

For the same expression the five owned unlock Prefabs should become three; the 70 owned Prefabs should become 68, plus one unchanged external dependency snapshot (69 total saved Prefab files). This is a same-input expectation, not a measurement of a newly generated bridge. Existing valid 71-file assets remain intact; no CID rewriting, migration or deletion was performed.

Persistence routes remain the native writer plus recursive dependency snapshots. No material, texture, geometry, or animation copy was added by this change. Preview and formal creation use the same unlock helper; migration uses the same native rule representation. The prior Odin compatibility fix remains in place.
